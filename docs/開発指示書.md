# 吃音村 Webアプリ 開発指示書

あなた（Claude Code）には、吃音当事者のためのオンライン自助グループ「吃音村」のWebアプリを、私と一緒に実装してもらいます。
`docs/prototype.html` は、画面・文言・デザイン・データ項目を確認するための試作品です。この試作をベースに、実際に複数の利用者が使えるWebアプリにしてください。

---

## 1. 吃音村の理念（実装判断の基準）

- 最も大切な使命は「吃音を抱えているのは、自分一人ではない」という感覚を届けること。
- 世界観は村、操作性はシンプルなSNS、中身は自助グループ。
- 理念は深く、仕組みはシンプルに。**文章そのものが主役**のアプリにする。
- 集会はAAの「言いっぱなし、聞きっぱなし」。コメントやアドバイスの機能は作らない。
- 当事者の語りが積み重なり、何年も後に来た人にも届くことに価値がある。
- 迷ったときは機能を増やさず、試作品の体験を忠実に再現する方を選ぶ。

## 2. 技術スタック

| 項目 | 採用するもの |
|---|---|
| フレームワーク | Next.js（App Router）＋ TypeScript |
| スタイル | CSS Modules または Tailwind CSS（試作品のデザイントークンを移植する） |
| 認証 | Firebase Authentication（メールアドレス＋パスワード、メール確認あり） |
| データベース | Cloud Firestore |
| ホスティング | Vercel（独自ドメイン kitsuonmura.com を使用予定） |
| 開発環境 | VS Code ＋ Claude Code |

- Firebaseの設定値は `.env.local` に置き、リポジトリにコミットしない。`.env.example` を用意する。
- kitsuonmura.com には既存の試作物（/test_farm01 など）がある可能性があるため、本番ドメインの設定を変更する前に必ず私に確認すること。

## 3. サービス構造とURL

### 公開エリア（ログイン不要・検索エンジンに公開）

| URL | 内容 |
|---|---|
| `/` | 公開トップ（村のイラスト、理念の一文、「はじめて村を訪れる」「住民の方はこちら」、できること、情報ガイドへの入口） |
| `/about` | 吃音村について（理念） |
| `/guide` | 吃音情報ガイドの一覧 |
| `/guide/[category]` | カテゴリ別ページ（全国の言友会、医療・相談窓口、子どもの吃音と保護者向け、学会・研究機関、オンライン自助グループ） |
| `/welcome` | オープニング演出 → 新規登録へ |
| `/signup` `/login` | 新規登録・ログイン |

### 住民限定エリア（ログイン必須・検索エンジン非公開）

| URL | 内容 |
|---|---|
| `/home` | ホーム（イラスト、「おかえりなさい、◯◯さん。」、今月の集会カード、図書館の新着、最近村に来た住民、情報ガイドへの入口） |
| `/residents` | 住民票の一覧 |
| `/residents/[uid]` | 住民票の詳細と吃音史 |
| `/meeting` | 今月の集会と、これまでの集会（アーカイブ）一覧 |
| `/meeting/[themeId]` | 過去の集会 |
| `/meeting/compose` | 今月のテーマで語る |
| `/library` | 図書館（テーマで絞り込み） |
| `/library/[bookId]` | 本棚の一冊の詳細 |
| `/library/new` | 本棚に一冊置く |
| `/me` | 自分（住民票へのリンク、届いた回数、自分の語りの一覧と削除、メニュー） |
| `/me/edit` | 住民票・吃音史の編集 |

- 下部タブは「ホーム／住民票／集会／図書館／自分」の5つ。住民限定エリアでのみ表示する。
- 未ログインで住民限定エリアにアクセスしたら `/login` に移動させる。

## 4. 機能仕様

文言・項目・画面構成は `docs/prototype.html` を正とする。以下は補足。

### オープニング（`/welcome`）
- 試作品と同じSVGアニメーション（村が建つ → 船が港に着く → 旅人が上陸 → 住民が迎える → 歓迎の4行が順に現れる）。
- 「スキップ」で最終状態に飛ぶ。`prefers-reduced-motion` ではアニメーションしない。
- 最後に「住民票をつくる」で `/signup` へ。自分ページから再生できる。

### 新規登録
- 入力はメールアドレス、パスワード、ニックネーム、年代のみ。ほかの住民票項目は後から書く。
- 登録時に `users/{uid}` を作成し、`/home` へ移動してトースト「住民票ができました。ようこそ、吃音村へ。」を出す。

### 住民票
- 項目：ニックネーム、年代、居住地域、職業やこれまでの経験、吃音の特徴、吃音が始まった時期、苦手な音、苦手な単語、苦手な場面、いま抱えている苦労、自分なりの工夫、趣味や好きなこと、これから挑戦したいこと、吃音史。
- ニックネームと年代以外はすべて任意。吃音史は最大10,000字で、文字数カウンターを付ける。
- 「苦手な場面」は「、」区切りで一覧画面にタグとして表示する。
- 吃音史には「約◯分で読めます」（500字＝1分で計算）を表示する。
- 吃音史にも共感ボタンを付ける。

### 集会
- 毎月1つのテーマ。最新のテーマが「今月の集会」。投稿できるのは今月のテーマだけ。
- 過去のテーマと語りはアーカイブとしてすべて読める（必須機能）。
- 投稿は本文のみ（最大5,000字）。コメント機能はない。
- テーマは管理者だけが作成できる（第7節）。

### 共感ボタン（集会・図書館・吃音史で共通）
- 表記は、未押下「あなたの言葉が届きました」、押下後「届きました」。件数を表示する。
- 1人1投稿につき1回。もう一度押すと取り消せる。
- 自分の投稿にはボタンを出さず「あなたの言葉が届いた人 ◯」と件数だけ表示する。
- 自分ページに、受け取った共感の合計「あなたの言葉は、これまでに◯回、誰かに届きました。」を表示する。

### 図書館
- 入力：書名（必須）、著者、テーマ（吃音／勇気／孤独／仕事／人生の意味／自己理解／夢・挑戦）、5つの問い（抱えていた苦労や悩み、この本との出会い、支えになった考え方や言葉、読んで考えたこと、自分の中で変わったこと）。
- 書影は当面、試作品と同じ「書名を縦書きした色付きの表紙」で表現する（外部APIは使わない）。
- 一覧はテーマで絞り込める。

### 自分
- 自分の集会の語り・本棚の投稿を一覧表示し、確認ダイアログを経て削除できる。
- 住民票の編集、情報ガイド、吃音村について、オープニング再生、ログアウト。

### 吃音情報ガイド
- データはFirestoreではなく、リポジトリ内のファイル（例：`content/guide.ts`）で管理し、静的生成する。
- 各項目：名称、種別、説明、向いている人、公式サイトURL、情報源、最終確認日。
- 試作品の掲載内容は仮のもの。URLは私が確認してから入れるので、空欄でも表示が崩れないようにする。

## 5. Firestore データ設計（案）

```
users/{uid}
  nickname, ageGroup, region, job, features, onset,
  hardSounds, hardWords, hardScenes, struggles, tips,
  hobbies, challenges, history,
  historyReactionCount, createdAt, updatedAt

themes/{themeId}
  month ("2026-11"), title, description, createdAt

meetingPosts/{postId}
  themeId, authorUid, text, reactionCount, createdAt

books/{bookId}
  authorUid, title, bookAuthor, tag,
  struggle, encounter, words, thought, change,
  reactionCount, createdAt

reactions/{targetType_targetId_uid}
  targetType ("post" | "book" | "history"), targetId, uid, createdAt
```

- 一覧に表示する投稿者名は、投稿時に `authorNickname` を複製して持つか、`users` を参照するかを検討し、理由とともに提案すること。
- 共感の件数は、`reactions` の作成・削除と `reactionCount` の±1を同じトランザクションで行う。

## 6. セキュリティ（最低限、今回必ず守ること）

- 住民限定のデータは**Firestoreのセキュリティルールでアクセスを制御**する。画面を隠すだけにしない。
  - 読み取り：ログイン済みでメール確認済みのユーザーのみ。
  - 作成・更新・削除：本人のドキュメントのみ。
  - `reactionCount` は±1の変更だけを許可し、`reactions` ドキュメントの作成・削除と整合しているかをルールで検証する（`getAfter` などを利用）。
  - `themes` の書き込みは管理者のみ。
- 住民限定ページには `noindex` を設定し、`robots.txt` とサイトマップから除外する。
- ユーザー入力はすべてエスケープして表示する（`dangerouslySetInnerHTML` を使わない）。
- 通報機能、危機的な投稿への対応、年齢制限などは後で検討する。今回は作らないが、後から追加しやすい構造にしておく。

## 7. 管理者

- 管理者はFirebaseのカスタムクレーム（`admin: true`）で判定する。
- 管理者だけが見られる簡易画面 `/admin/themes` で、集会テーマを追加できるようにする。
- カスタムクレームを付与するスクリプト（`scripts/set-admin.ts`）を用意する。

## 8. デザイン

- 試作品の `:root` のデザイントークン（色、フォント）をそのまま移植する。
  - 背景は生成り、アクセントは深緑と淡い茶色。
  - 見出しは Zen Old Mincho、本文は Zen Kaku Gothic New（`next/font/google` で読み込む）。
- 水彩画風の村のSVGはコンポーネント化し、オープニング（アニメーションあり）とホーム・公開トップ（静止）で使い回す。
- スマートフォンを最優先にする。表示幅は最大480pxの一列で、PCでは中央に寄せる。
- 長文を読む画面にはイラストを置かず、本文は16px・行間1.95程度にして読みやすさを優先する。
- ランキング、ポイント、派手な演出は入れない。

## 9. SEO

- 公開ページにはページごとに `title` と `description` を付け、OGP を設定する。
- `sitemap.xml` と `robots.txt` を生成する。
- 主な検索語は「吃音 自助グループ」「吃音 言友会」「吃音 仲間」「吃音 コミュニティ」「吃音 相談」など。ページを水増しせず、内容で応える。

## 10. 今回作らないもの（保留・廃止）

コメント、ダイレクトメッセージ、本の紹介と感謝の手紙、当事者研究室、Kind Words的な交流、農園・苦労の種・水やり、マップ移動型のゲーム、住民の検索機能。
これらは提案もしなくてよい。

## 11. 進め方

1. まずこの指示書と `docs/prototype.html` を読み、実装計画（ディレクトリ構成、使うライブラリ、作業の順番）を提案して、私の承認を待つこと。
2. 承認後、以下の順で1段階ずつ実装する。各段階の終わりに動作確認の方法を伝え、git にコミットする。
   1. プロジェクト作成、デザイントークン、共通レイアウト、下部タブ、村のSVG
   2. 公開エリア（トップ、理念、情報ガイド、オープニング）
   3. Firebase認証（登録、ログイン、ログアウト、未ログイン時の移動）
   4. 住民票（一覧、詳細、編集、吃音史）
   5. 集会（今月、投稿、アーカイブ）と共感ボタン
   6. 図書館（一覧、詳細、投稿、絞り込み）
   7. 自分ページ（届いた回数、自分の語りの削除）
   8. セキュリティルール、管理者画面、SEO設定、Vercelへのデプロイ
3. 開発用に、試作品と同じ架空のサンプルデータを投入するシードスクリプト（`scripts/seed.ts`）を用意する。本番環境には投入しない。
4. Firestoreのセキュリティルールは Firebase Emulator でテストを書いて確認する。
5. 不明な点や、仕様に書かれていない判断が必要な点は、推測で進めずに私に質問すること。
